= Accelerating Ansible Delivery with AI

Hands-on labs for using Codex or Cursor with Ansible: migrate a Python NetBox installer, compare models and effort, and deliver NetBox on AWS as a team.

https://redhat-services-platform-team.github.io/ansible-amers-ai-workshop/[Read the workshop on GitHub Pages].

== Repository layout

* `docs/`: the overview and four lab pages in AsciiDoc, one HTML layout, and the build/check scripts.
* `docs/assets/`: the existing Red Hat theme, logo, syntax highlighting, and small site customizations.
* `workshop-content/`: learner code, sample configuration, project briefs, and checklists.
* `instructor_automation/`: Ansible provisioning, teardown, and tests for the workshop Git server. See link:instructor_automation/README.md[the instructor guide].
* `.github/workflows/gh-pages.yml`: build checks and GitHub Pages deployment.

== Edit and preview the docs

Install Ruby (3.3 is used in CI) and Python 3.9 or later, then install the single build dependency once:

[source,sh]
----
gem install asciidoctor -v 2.0.23 --no-document
----

From the repository root:

[source,sh]
----
ruby docs/build.rb
python3 docs/check.py
python3 -m http.server 8080 --bind 127.0.0.1 --directory www
----

Open http://localhost:8080. Stop the server with Ctrl+C.
After editing, rerun the build and refresh the browser. Uncommitted edits are included.
The build recreates `www/`, which is ignored by Git. No containers, Node.js, or Antora are needed.
Once Asciidoctor is installed, building and viewing the site works offline.

Edit `docs/index.adoc` for the overview or a numbered `.adoc` file for a lab.
Navigation and previous/next links come from the numbered filenames and page titles.
Use `xref:02-shell-to-ansible.adoc[Lab 2]` for links between pages.
Put any new images in `docs/assets/` and use `image::filename.png[Description]`.
Adjust `docs/layout.erb` for shared HTML and `docs/assets/site.css` for appearance.
The check script validates generated local links, section anchors, assets, and the publication file list.

The original Showroom v0.0.1 stylesheet is retained in `docs/assets/theme.css`, with its fonts and icons embedded so it is self-contained.
`docs/assets/highlight.js` comes from the same theme bundle; `workshop-banner.png` is the generated Red Hat Services workshop banner, based on the supplied design reference.
Theme source: https://github.com/rhpds/rhdp_showroom_theme/releases/tag/v0.0.1[RHDP Showroom v0.0.1].
Upstream license notices are in `docs/assets/LICENSE.txt`.

== GitHub Pages

Keep *Settings → Pages → Build and deployment → Source* set to *GitHub Actions*.
In *Settings → Environments → github-pages → Deployment branches and tags*, allow all repository branches (select *No restriction*).
The workflow needs permission to push generated files to `gh-pages`; repository rules must allow the GitHub Actions bot to update that branch.

Pushing to `main` publishes the workshop at the site root.
Pushing to any other source branch publishes an independent copy under `/branches/<branch>/`.
For example, `rh1` publishes at https://redhat-services-platform-team.github.io/ansible-amers-ai-workshop/branches/rh1/.
Simple branch names containing letters, numbers, underscores, and hyphens retain their names.
Other names (including names containing `/`) use a readable prefix plus a hash; the workflow summary reports the URL.

The workflow stores the combined generated site in `gh-pages` and deploys it using GitHub Actions.
Do not edit that branch manually or select it as the Pages publishing source.
Updates are queued so publishing one branch preserves the other previews.
Deleting a source branch removes its preview on the next successful cleanup deployment.
Deletion handling requires this workflow and `docs/publish.py` on the default branch.
The main site is retained if `main` is deleted.

Pull requests build and check the docs without publishing.
Manual workflow runs publish the selected branch, except the reserved `gh-pages` branch.
Existing branches need this workflow and publishing script before pushes on them can publish previews; merge or cherry-pick the changes into those branches, then push or run the workflow manually.
For local review, run the preview commands above.

Old `/modules/<page>.html` and `/modules/master/<page>.html` bookmarks redirect to the new flat URLs, preserving section anchors.
Only generated documentation and `docs/assets/` are published. Instructor credentials and learner runtime output stay outside the site.
