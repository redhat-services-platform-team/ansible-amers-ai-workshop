== Plan and collaboration

* [ ] We agreed on customer scope, architecture, and acceptance checks.
* [ ] We divided work and agreed on shared variables and file ownership.
* [ ] We used Lab 3 findings to choose models and effort settings.
* [ ] Teammates reviewed the generated changes and can explain the implementation.

== Delivery

* [ ] AWS hosts run the chosen NetBox infrastructure.
* [ ] Ansible installs and configures NetBox without delegating the migration to the original installer.
* [ ] Dependencies, supported versions, defaults, and intentional behavior changes are documented.
* [ ] Installation and rerun checks cover saved secrets, release state, services, and application health.
* [ ] AWS VPC IPAM data syncs into team-scoped NetBox records without duplicates.
* [ ] Demo hosts have NetBox VM or device records, interfaces, reachable primary IPs, and a team tag.
* [ ] Host addresses relate to the demonstrated IPAM-derived network and VRF.
* [ ] NetBox dynamic inventory selects only the intended demo hosts.
* [ ] An Ansible play runs successfully against those AWS hosts.
* [ ] A NetBox record change updates inventory membership after refresh.

== Handover

* [ ] The customer demo explains the problem, automation, evidence, and remaining limitations.
* [ ] Another teammate can follow the README to operate the deployment and sync.
* [ ] Source and sanitized evidence contain no credentials or private inventory exports.
* [ ] Cleanup removes only team-owned resources, or retained resources have an owner and expiry.
