= Customer brief: Switchboard Supply

Switchboard Supply uses NetBox to record its networks and hosts.
A Python installer has accumulated years of undocumented changes, and operators still copy AWS host addresses into static Ansible inventories.
The customer wants Ansible to deploy NetBox and select hosts from its records.

== What the customer needs

Deliver Ansible content that installs and configures NetBox on AWS hosts the team is authorized to use.
Base the migration on `workshop-content/02-shell-to-ansible/legacy/install_netbox.py` and review it against the migration checklist.
You may change the architecture and defaults if you explain the reason and test the resulting behavior.

Manually add your demo AWS hosts through the NetBox UI.
Create VM or device records, interfaces, primary IP addresses, and a team-specific tag.
Use `netbox.netbox.nb_inventory` to query those records and run Ansible against the selected hosts.

The customer needs to see how a host entered in NetBox becomes a target for Ansible.
Show that changing a NetBox record changes inventory membership after refresh.
Document the manual host-entry steps so another operator can follow them.

== Questions to settle as a team

* Which AWS account, region, and resources can we use? Who owns cleanup?
* Which NetBox version, OS, and deployment layout will we support?
* Which installer behaviors will we preserve, improve, or leave unsupported?
* How will we protect secrets and keep database and cache access private?
* Which demo hosts will we add to NetBox, and what tag will select them?
* How will the control workstation reach the hosts returned by NetBox?
* What evidence will convince the customer that installation, reruns, and inventory work?

== Acceptance criteria

[cols="2,3",options="header"]
|===
| Customer request | Evidence to bring to the demo
| Repeatable NetBox installation | Reviewed Ansible project, declared dependencies, AWS host details, and healthy application and services
| Safe reruns | A second deployment run, preserved credentials and release, and explanations for remaining changes
| Manual host entry | Demo AWS hosts entered through the NetBox UI with interfaces, primary IPs, and a team tag
| NetBox dynamic inventory | A filtered query using `netbox.netbox.nb_inventory` and a successful Ansible play against the selected AWS hosts
| Dynamic host selection | A NetBox record change that changes inventory membership without editing a static list
| Maintainable handover | README, architecture decisions, verification evidence, known limitations, recovery notes, and teardown instructions
|===

Keep the demo small enough to understand and test.
List the changes and tests needed before production use.
