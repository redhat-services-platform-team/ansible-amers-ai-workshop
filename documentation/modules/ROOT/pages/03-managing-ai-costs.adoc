= Lab: Managing AI Costs

[abstract]
Use the same shell-to-Ansible task as Module 2 to compare models, usage, and spend—and write three guardrails.

== Learning Objectives

After completing this module, you will be able to:

* Name what drives AI usage cost (pools, model, tokens, Chat vs Agent)
* Run the **same** migration prompt with three models and record time, turns, and quality
* Connect Module 2 results to dollars-and-cents habits (cheaper model first, small context, verify before re-prompt)
* Write three personal rules to use AI more efficiently

* Complete xref:02-shell-to-ansible.adoc[Module 2: Shell-to-Ansible Migration] or skim `workshop-content/02-shell-to-ansible/legacy/configure-workshop-app.sh` and `prompt.md` so the task is familiar.

== Step 1: Record your billing context

_Facilitator deck: slides 3–4 (what you pay for; usage pools)._

. Open link:https://cursor.com/dashboard/spending[Spending,window=_blank].
. Write down: **billing period reset date** and the **names of the usage pools** you see (for example Cursor Models vs Other Models).
. In Cursor, note your **current chat/agent model** and Router mode if shown (Cost, Balance, Intelligence, or pinned model).
. **Record** pool names and reset date at the top of `lab-scorecard.adoc` or your notebook.

== Step 2: Pattern check (2 minutes)

_Facilitator deck: slide 9 (usage patterns)._

. For each pattern below, write **one example** from Module 2, this workshop, or your job (one line each):

* *Surgical ask* — one or two files, narrow change
* *Retry loop* — vague prompt or many fix-it-again turns
* *Agent marathon* — long thread with many tool steps

== Step 3: Prepare three migration runs (same task as Module 2)

_Facilitator deck: slides 5–6, 10–11 (model choice, context size, scorecard)._

You will migrate `configure-workshop-app.sh` to Ansible **three times**. Each run uses a **new** chat thread and the **same** `prompt.md`.

. Create three output folders, for example:

+
[source,bash]
----
workshop-content/02-shell-to-ansible/output/<your-name>/run-a/
workshop-content/02-shell-to-ansible/output/<your-name>/run-b/
workshop-content/02-shell-to-ansible/output/<your-name>/run-c/
----

. Open `workshop-content/02-shell-to-ansible/prompt.md` and keep it ready to copy-paste verbatim each time.
. Decide which model you will use for each run (facilitator may assign):

* **Run A** — cost-efficient (for example Composer or Cost Router default)
* **Run B** — balanced / mid-tier
* **Run C** — frontier or team “escalation” model (or repeat B with Agent if your plan has no frontier)

== Step 4: Run A

. New Cursor Chat or Agent thread; select **Run A** model.
. Attach **only** `workshop-content/02-shell-to-ansible/legacy/configure-workshop-app.sh`.
. Paste the full `prompt.md`; tell the model to write the playbook under your `run-a/` folder.
. Accept or edit the result until `ansible-playbook --syntax-check` passes on your new playbook.
. **Before** opening Spending, fill scorecard row **Run A**: model, Chat or Agent, minutes, user turns, quality (merge / edit / discard), notes (context size, rework).
. Glance at Spending; note subjective usage **low / medium / high** for this run (optional column on scorecard).

== Step 5: Run B

. **New thread.** Same attachment. **Same** `prompt.md` text. Save under `run-b/`.
. Syntax-check the playbook.
. Fill scorecard row **Run B** (same columns as Run A).

== Step 6: Run C

. **New thread.** Same rules as Run B. Save under `run-c/`.
. Fill scorecard row **Run C**.

. Stop each run at definition of done in `prompt.md` or after **15 user turns**, whichever comes first.

== Step 7: Compare Module 2 and Runs A–C

_Facilitator deck: slides 2, 12–13 (bridge from Module 2; cost vs delay vs rework)._

. If you completed Module 2, compare scorecard rows *Module 2 — Model A/B* to *Run A/B/C*.
. Answer in writing (scorecard notes or notebook):

* Which run had the **fewest user turns** for acceptable Ansible?
* Which run would you **ship** under a tight monthly usage cap?
* Did a **more expensive model** avoid rework, or did it only burn tokens?

== Step 8: Three personal rules

_Facilitator deck: slide 12._

. On `lab-scorecard.adoc`, complete **Personal optimization rules** (three sentences you will actually follow).

Examples: cheap model first on small migrations; only attach the shell script; syntax-check before a second Agent message.

== Step 9 (optional): CLI agent

_Facilitator deck: slide 7._

. Repeat **Run A** with `cursor-agent` using the same `prompt.md` and script path; add a note on the scorecard if turns or usage differ from in-editor Agent.
