= Lab: Cursor Workspace Setup

[abstract]
Request Cursor access, install Cursor, copy the sample Dev Container config to the repository root, and run this workshop inside the community Ansible Development Tools (ADT) container with *Podman*.

== Learning Objectives

After completing this module, you will be able to:

* Request and obtain Cursor access for Red Hat associate use
* Install Cursor and the Anysphere Dev Containers extension
* Copy sample `.devcontainer` and `.vscode` files to the repository root and understand what they do
* Reopen the workshop in the ADT Dev Container via Podman
* Run a sample playbook from the Dev Container terminal

== Prerequisites

.Prerequisites
====
* *Podman* installed and working on your workstation (Podman Desktop is recommended on macOS and Windows)
* On macOS or Windows: a Podman *machine* created and *running*
* On Linux: the user Podman API socket enabled (`systemctl --user enable --now podman.socket`)
* Ability to install desktop software (Cursor) and receive email at your Red Hat address
====

.Verify Podman
====
[source,sh]
----
podman version
podman info
podman run --rm quay.io/podman/hello
----

* `podman info` must succeed.
* On macOS/Windows, `podman machine list` should show the default machine as *running*.
====

[NOTE]
====
This lab does *not* walk through installing Podman.
If these checks fail, install link:https://podman-desktop.io/[Podman Desktop,window=_blank] (or use your platform package manager) and return here.
====

== 1: Overview

link:https://cursor.com[Cursor,window=_blank] is an AI-enhanced code editor built on a VS Code–compatible foundation.
At Red Hat, Cursor is an approved AI development tool for associate use (subject to local laws and Works Council availability).

This lab gets you from *no Cursor install* to a verified workspace at the *repository root*, running *inside* the community Ansible Development Tools container via *Podman*.

You will copy these sample files from `workshop-content/01-cursor-workspace/samples/` to the repository root:

* `.devcontainer/devcontainer.json` — ADT container definition for Podman
* `.vscode/settings.json` — points Dev Containers at `podman`

Those root copies are gitignored so each participant keeps their own local settings.

== 2: Request Cursor Access

.Procedure
====
. Review the internal Cursor overview on The Source: link:{cursor_source_url}[Cursor — AI Tools,window=_blank].
. Confirm you are in a supported region.
+
Cursor is available upon request to developers at Red Hat, subject to local laws and regulations.
Works Council–supported countries currently approved for use include the Netherlands, Germany, Austria, Spain, and France.
Cursor is *not* available in China or the regions of Crimea, Donetsk, and Luhansk in Ukraine.
Accessing Cursor through a VPN solely to bypass regional restrictions violates the contractual terms of use.
. Submit a request using the Cursor access request form (VPN required): link:{cursor_access_request_url}[Cursor Access Request,window=_blank].
. Wait for the confirmation email (typically within about five minutes).
Follow the link in the email to complete Cursor account access.
. If you do not receive email, check junk/spam first, then contact your facilitator or `pge-cloudops@redhat.com`.
====

== 3: Install Cursor

.Procedure
====
. Open link:https://cursor.com/download[Cursor download,window=_blank] and select the installer for your OS (macOS, Windows, or Linux).
+
image::01-cursor-workspace/cursor-download-page.png[Cursor download page with macOS, Windows, and Linux installers,width=720]
. Run the installer and launch Cursor.
. Sign in when prompted using the account that received Cursor access.
+
image::01-cursor-workspace/cursor-sign-in.png[Cursor welcome screen with Sign in button,width=720]
====

.Verification
====
* Cursor launches without license or authentication errors.
====

== 4: Install the Dev Containers Extension

.Procedure
====
. In Cursor, open *Extensions* (`Ctrl+Shift+X` / `Cmd+Shift+X`).
. Search for *Dev Containers* published by *Anysphere*.
. Install *Dev Containers* (`anysphere.remote-containers`).
+
image::01-cursor-workspace/cursor-dev-containers-extension.png[Extensions view showing Dev Containers by Anysphere with Install button,width=720]
. Reload Cursor if prompted.
====

== 5: Clone the Workshop and Open the Repository Root

.Procedure
====
. Clone the workshop repository:
+
[source,sh]
----
git clone {workshop_repo_url}.git
cd ansible-amers-ai-workshop
----
. In Cursor: *File → Open Folder…* and select the *repository root*:
+
----
ansible-amers-ai-workshop
----
====

== 6: Copy Sample Dev Container Config to the Repository Root

Cursor looks for `.devcontainer/` and `.vscode/` at the folder you opened (the repository root).
Sample files are provided under Lab 1; you copy them into place so you see how the setup works.

.What each file does
====
* `.devcontainer/devcontainer.json` — tells Dev Containers which image to run (ADT), container options for Podman, and which extensions to install inside the container
* `.vscode/settings.json` — sets `dev.containers.dockerPath` to `podman` so Cursor uses Podman instead of Docker
====

.Procedure
====
. From the repository root, copy the samples:
+
[source,sh]
----
cp -R workshop-content/01-cursor-workspace/samples/.devcontainer .
cp -R workshop-content/01-cursor-workspace/samples/.vscode .
----
. Confirm the files exist at the root:
+
[source,sh]
----
ls -la .devcontainer/devcontainer.json .vscode/settings.json
----
. Open `.devcontainer/devcontainer.json` and `.vscode/settings.json` in Cursor and skim them so you know what you copied.
====

.Verification
====
In *Settings*, search for `docker path` and confirm it shows `podman`.

image::01-cursor-workspace/cursor-docker-path-settings-ui.png[Settings UI showing Dev Containers Docker Path set to podman,width=720]
====

[NOTE]
====
Root `.devcontainer/` and `.vscode/` are listed in `.gitignore`.
Do not commit your copies—each person manages their own local config.
====

== 7: Reopen in the ADT Dev Container

.Procedure
====
. Open the Command Palette and run *Dev Containers: Reopen in Container*.
+
image::01-cursor-workspace/cursor-reopen-in-container.png[Command Palette with Dev Containers Reopen in Container selected,width=720]
. Wait for Podman to pull/start `{ansible_dev_tools_image}` and for the status bar to show a Dev Container connection.
. Open *Terminal → New Terminal*.
This shell is *inside* the ADT container.
====

.Verification
====
[source,sh]
----
ansible-playbook --version
ansible-lint --version
----
====

== 8: Run the Sample Playbook

.Procedure
====
. In the Dev Container terminal:
+
[source,sh]
----
cd workshop-content/01-cursor-workspace
ansible-playbook playbooks/hello.yml
----
====

.Expected result
====
The playbook completes successfully and prints a hello message with the Ansible version from the ADT container.
====

|===

[#troubleshoot-podman]
== 10: Troubleshooting

[cols="1,2"]
|===
| Symptom | What to try

| Dev Containers still calls `docker`
| Confirm you copied `.vscode/settings.json` to the *repository root*, reopen the folder, confirm `which podman` works

| No Dev Container prompt / config not found
| Confirm `.devcontainer/devcontainer.json` is at the repository root (not only under `samples/`)

| `podman machine` not running
| `podman machine start` or start the machine in Podman Desktop

| Permission / socket errors on Linux
| `systemctl --user enable --now podman.socket`

| GUI-launched Cursor cannot find `podman`
| Launch Cursor from a shell where `podman` is on `PATH`
|===

Use *Dev Containers: Show Log* from the Command Palette while reproducing failures.
