= {lab_name}

Use Codex or Cursor with Ansible to migrate a Python NetBox installer, compare models and reasoning effort, and deliver a team NetBox project on AWS.

== Prerequisites

* Basic Linux command-line skills and familiarity with YAML and scripting.
* A RHEL or macOS workstation with a working Ansible installation.
* Permission to install your chosen AI tool and access to enterprise Codex or an approved Cursor account.
* Optional Podman access to preview the documentation locally.

Lab 2's generation and review steps run on your workstation.
Lab 4 requires an AWS environment your team can use for testing and deployment.
The workshop does not require OpenShift, AAP, or Showroom services.

== Labs

. xref:01-cursor-workspace.adoc[Workspace setup]. Configure Codex or Cursor with your local Ansible tools, using the CLI or desktop interface.
. xref:02-shell-to-ansible.adoc[Python-to-Ansible NetBox migration]. Write your own prompt and make one initial port with Composer in Cursor or Luna in Codex.
. xref:03-managing-ai-costs.adoc[Comparing models and effort]. Repeat the migration with fixed inputs, change models and effort levels, and compare output, review work, time, and usage.
. xref:04-aws-lab-provisioning.adoc[Customer NetBox delivery project]. Migrate the installer and deploy NetBox on AWS as a team. Add hosts in NetBox and query them through Ansible dynamic inventory.
