Lab: Shell-to-Ansible Migration

Refactor a legacy shell script into Ansible using AI—and compare two models on the same task.

Learning Objectives

After completing this module, you will be able to:

  • Read a legacy shell script and state what it changes on a system

  • Use AI assistance to produce a minimal Ansible playbook from that script

  • Run the same migration prompt with two different models and compare results

  • Record observations that Module 3 will use for cost comparison

Before you start

  • Lab files live in workshop-content/02-shell-to-ansible/.

  • Scaffold details and open questions for doc owners: workshop-content/02-shell-to-ansible/REVIEW-NOTES.md.

Step 1: Open the legacy script

  1. In Cursor, open workshop-content/02-shell-to-ansible/legacy/configure-workshop-app.sh.

  2. Run it once in a terminal if you want (optional): bash workshop-content/02-shell-to-ansible/legacy/configure-workshop-app.sh

  3. In your notes, write three bullets: what directories/files it creates, what variables it uses, and one thing that would be hard to maintain as a script at scale.

Step 2: Create your output folder

  1. Create a folder for your playbook, for example: workshop-content/02-shell-to-ansible/output/<your-name>/

  2. You will save your generated site.yml (or equivalent) there—not in the repo root.

Step 3: Migrate with Model A

  1. Start a new Cursor Chat or Agent thread.

  2. Select Model A (use the cost-efficient or “default” model your facilitator names for this run).

  3. Attach only workshop-content/02-shell-to-ansible/legacy/configure-workshop-app.sh unless you must add one more file.

  4. Open workshop-content/02-shell-to-ansible/prompt.md, copy the full text, paste into the chat, and send.

  5. Apply the suggested changes; save the playbook under your output folder.

  6. Run: ansible-playbook --syntax-check workshop-content/02-shell-to-ansible/output/<your-name>/site.yml (adjust path if the model used a different filename).

  7. Record: model name, minutes, number of prompts until you accepted the result, and merge / edit / discard—in workshop-content/03-managing-ai-costs/lab-scorecard.adoc row Module 2 — Model A.

Step 4: Migrate with Model B

  1. Start a new thread (do not continue Model A’s conversation).

  2. Select Model B (facilitator names the second model—often more capable or balanced).

  3. Attach the same shell script only.

  4. Paste the same prompt.md text unchanged.

  5. Save to a new file or subfolder if you want to keep both (for example site-model-b.yml).

  6. Run ansible-playbook --syntax-check on the new playbook.

  7. Record the same metrics in scorecard row Module 2 — Model B.

Step 5: Compare the two playbooks

  1. Open both playbooks side by side.

  2. In your notes or scorecard Notes column, answer:

    • Which model needed more follow-up messages?

    • Which produced a larger diff?

    • Which playbook you would rather run in production (one sentence).

Module 3 reuses the same script and same prompt to compare cost (Runs A/B/C). Completing this module gives you baseline rows on the scorecard.
